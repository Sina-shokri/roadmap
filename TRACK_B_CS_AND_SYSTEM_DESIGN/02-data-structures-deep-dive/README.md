## 1️⃣ کالبدشکافی `ArrayList` در جاوا

کلاس `ArrayList` در واقع یک آرایه ساده استاتیک `Object[] elementData` در پشت صحنه دارد:
1. ظرفیت پیش‌فرض اولیه: **۱۰ خانه**.
2. وقتی تعداد عناصر به ظرفیت برسد (`size == capacity`)، متد `grow()` فراخوانی می‌شود:
   $$\text{newCapacity} = \text{oldCapacity} + (\text{oldCapacity} \gg 1) = 1.5 \times \text{oldCapacity}$$
   یعنی اندازه آرایه ۵۰٪ افزایش می‌یابد.
3. یک آرایه جدید با اندازه بزرگتر در هیپ ساخته شده و داده‌ها با دستور پرسرعت `System.arraycopy` به آرایه جدید منتقل می‌شوند.

> 💡 **نکته بهینه‌سازی بک‌اند:** اگر می‌دانید لیستی با حدود ۵,۰۰۰ رکورد از دیتابیس دریافت خواهید کرد، حتماً ظرفیت اولیه را مقداردهی کنید: `new ArrayList<>(5000)`. این کار مانع از چندین بار تخصیص حافظه و کپی مکرر در هیپ می‌شود!

## 2️⃣ نبرد کلاسیک: `ArrayList` در برابر `LinkedList`

خیلی از کتاب‌های قدیمی دانشگاهی می‌گویند: *"برای درج و حذف از `LinkedList` استفاده کنید چون $O(1)$ است!"* اما در سخت‌افزارهای مدرن، این حرف تقریباً همیشه غلط است!

```
[ ArrayList در حافظه: خانه‌های پشت‌سرهم (Contiguous) ]
[ عنصر ۰ ][ عنصر ۱ ][ عنصر ۲ ][ عنصر ۳ ][ عنصر ۴ ]
👉 سازگار با CPU L1/L2 Cache Prefetching (فوق‌العاده سریع)

[ LinkedList در حافظه: گره‌های پراکنده در سراسر Heap ]
[ گره ۱ (اطلاعات + ۲ پوینتر) ] ──پوینتر──> [ گره ۲ ] ──پوینتر──> [ گره ۳ ]
👉 ایجاد CPU Cache Miss پی‌درپی و مصرف حافظه بسیار بیشتر (سربار پوینترها)
```

**نتیجه تجربی:** در ۹۹.۹٪ مواقع در بک‌اند، `ArrayList` به دلیل سرعت حافظه کش پردازنده بسیار سریع‌تر از `LinkedList` عمل می‌کند، مگر در مواردی که نیاز به صف دوطرفه (`Deque`) یا درج صرفاً در ابتدای لیست بدون دسترسی ایندکس داشته باشیم.

## 3️⃣ شاهکار مهندسی: نحوه کار `HashMap` در جاوا

کلاس `HashMap` پرکاربردترین ساختمان‌داده در بک‌اند جاوا است. ساختار داخلی آن به شرح زیر است:

```
آرایه‌ای از باکت‌ها (Buckets) با اندازه توان ۲ (پیش‌فرض ۱۶):
[0] ──> null
[1] ──> [Key1:Val1] ──> [Key2:Val2] (LinkedList Chaining برای تصادم)
[2] ──> null
[3] ──> [TreeNode (Red-Black Tree)] 👈 اگر تعداد تصادم‌ها بیش از ۸ شود!
...
[15] ──> null
```

### الگوریتم ذخیره‌سازی (`put`):
1. **محاسبه هش کلید:** با اجرای تابع `key.hashCode()` و سپس یک تابع هش تکمیلی جاوا برای پخش بیت‌ها:
   ```java
   static final int hash(Object key) {
       int h;
       return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
   }
   ```
2. **یافتن ایندکس باکت:** با استفاده از عملیات بیتی پرسرعت به جای باقیمانده (`%`):
   $$\text{index} = (n - 1) \& \text{hash}$$
   (چون اندازه آرایه همیشه توانی از ۲ است).
3. **بررسی تصادم (Collision Resolution):**
   - اگر باکت خالی بود، شیء `Node<K,V>` مستقیماً در آن قرار می‌گیرد.
   - اگر باکت پر بود، گره جدید به انتهای لیست پیوندی آن باکت متصل می‌شود.
4. **تبدیل به درخت (Treeification) در Java 8+:**
   - اگر طول زنجیره یک باکت به **۸ گره** برسد (`TREEIFY_THRESHOLD = 8`) و اندازه کل جدول حداقل ۶۴ باشد، جاوا به صورت هوشمندانه آن باکت را از LinkedList به **Red-Black Tree** تبدیل می‌کند!
   - این بهینه‌سازی انقلابی باعث می‌شود جستجو در بدترین حالت تصادم عمدی هکرها (Hash Collision DoS Attack) از $O(n)$ به **$O(\log n)$** تبدیل شود!
5. **بازآرایی (Resizing / Rehashing):** وقتی تعداد عناصر از ضریب بار (Load Factor = 0.75) فراتر رود ($16 \times 0.75 = 12$)، اندازه جدول ۲ برابر می‌شود (۳۲).

## 4️⃣ ساختارهای درختی و هیپ (Heap & PriorityQueue)

- **Binary Search Tree (BST):** درختی که هر گره چپ کوچکتر و گره راست بزرگتر است. اگر متوازن نباشد، به لیست خطی $O(n)$ تنزل می‌یابد.
- **Red-Black Tree (درخت سرخ-سیاه):** درخت دودویی خودمتوازن با رنگ‌آمیزی گره‌ها که تضمین می‌کند ارتفاع درخت هرگز از $2 \log(n+1)$ فراتر نرود (استفاده‌شده در `TreeMap` و `TreeSet`).
- **PriorityQueue (Min/Max Heap):** ساختاری ایده‌آل برای یافتن کمترین یا بیشترین عنصر در زمان $O(1)$ و درج/خروج در زمان $O(\log n)$.
  - *کاربرد در بک‌اند:* مدیریت صف وظایف اولویت‌دار، الگوریتم‌های زمان‌بندی (Scheduler)، و الگوریتم‌های مسیریابی نظیر Dijkstra.

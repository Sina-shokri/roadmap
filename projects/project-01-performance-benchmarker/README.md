# 🛠️ پروژه ۱: ابزار خط فرمان بنچمارک ساختمان‌داده‌ها و الگوریتم‌ها (Performance Benchmarker CLI)

یک ابزار خط فرمان تعاملی و ماژولار به زبان جاوا خالص (Java 21) بدون هیچ فریم‌ورک خارجی برای اندازه‌گیری و مقایسه تجربی سرعت و مصرف حافظه ساختمان‌داده‌ها و الگوریتم‌های مختلف.

---

## 🎯 اهداف یادگیری در این پروژه
- پیاده‌سازی دستی ساختمان‌داده‌های جنریک (`CustomArrayList`, `CustomLinkedList`, `CustomHashMap`).
- استفاده از `System.nanoTime()` و `Runtime.getRuntime()` برای اندازه‌گیری زمان و حافظه.
- تجربه ملموس مفهوم Big-O با نمودارهای متنی در ترمینال.
- استفاده از قابلیت‌های مدرن جاوا: `record`، `sealed interfaces` و `switch pattern matching`.

---

## 📋 صورت مسئله و نیازمندی‌های نرم‌افزاری

برنامه باید در هنگام اجرا یک منوی متنی در ترمینال ارائه دهد:

```text
=====================================================
🚀 JAVA PERFORMANCE BENCHMARK SUITE (Java 21)
=====================================================
1. مقایسه درج در ابتدا: ArrayList در برابر LinkedList
2. مقایسه دسترسی تصادفی (Random Access با ایندکس)
3. مقایسه جستجو: Linear Search در برابر Binary Search
4. شبیه‌سازی تصادم هش و افت پرفورمنس در HashMap
5. خروج
انتخاب شما: 
```

### سناریوهای آزمون:
1. **تست درج (Insertion Test):**
   - درج $N = 100,000$ عنصر در ابتدای لیست (`index = 0`).
   - مقایسه `ArrayList` با `LinkedList`.
   - *خروجی مورد انتظار:* اثبات کند که درج در ابتدای `ArrayList` به دلیل شیفت دادن خانه‌ها $O(n^2)$ زمان کل می‌برد، در حالی که در `LinkedList` زمان $O(n)$ است.
2. **تست دسترسی تصادفی (Random Access Test):**
   - خواندن تصادفی ۱۰۰,۰۰۰ ایندکس از میان لیست‌های ۱ میلیونی.
   - *خروجی مورد انتظار:* پیروزی مطلق `ArrayList` ($O(1)$ در برابر $O(n)$).
3. **تست شبیه‌سازی تصادم (Hash Collision Attack):**
   - ساخت کلاسی با متد `hashCode()` عمداً ثابت (`return 42;`) و مقایسه پرفورمنس `put` و `get` آن با کلیدی با هش استاندارد.
   - اثبات بهینه‌سازی جاوا در تبدیل باکت به Red-Black Tree.

## ✅ چک‌لیست پیاده‌سازی پروژه

- [ ] تعریف رکورد `BenchmarkResult` برای ثبت نام تست، تعداد داده ($N$)، زمان سپری‌شده (میلی‌ثانیه) و حافظه مصرفی (مگابایت).
- [ ] پیاده‌سازی اینترفیس `BenchmarkRunner` و جداسازی هر تست در یک کلاس مجزا (رعایت Single Responsibility).
- [ ] ایجاد متد کمکی برای پاکسازی حافظه با `System.gc()` قبل از شروع هر تست برای دقت بیشتر نتایج.
- [ ] چاپ جدول مقایسه‌ای زیبا در کنسول به همراه درصد تفاوت کارایی.
- [ ] نوشتن تست‌های واحد با JUnit 5 برای اطمینان از صحت کارکرد متدها.

## 💻 کدهای راهنما (Starter Code)

```java
public record BenchmarkResult(
    String operationName,
    int dataSize,
    long durationNanos,
    long memoryUsedBytes
) {
    public double durationMillis() {
        return durationNanos / 1_000_000.0;
    }

    public double memoryMegabytes() {
        return memoryUsedBytes / (1024.0 * 1024.0);
    }
}
```
